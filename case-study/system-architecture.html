Signal-Based Outreach — System Architecture

Part 3 Weekly Claude Code agent. 50k ICP universe → Fit × Intent scoring → SDR Google Sheets + Amplemarket programmatic.

1The Architecture

Scheduled cron · runs every Monday at 6 AM · end-to-end in under 30 minutes. One Claude Code orchestrator running 3 Python pipeline stages, with the LLM invoked at 2 specific points (sub-type classification in Stage 1, AI hook generation in Stage 3). Honest agent count: 2. The pipeline starts from a Salesforce query (territory + status filters do most of the exclusion work natively), and writes back to Salesforce. SDRs work in a per-territory Google Sheet; Tier 1 = manual compose with AI hook, Tier 2 = auto-fires by default.

2Components — 1 Agent + 3 Pipeline Stages

Honest split: 2 actual agents (Claude Code orchestrator + the LLM hook agent embedded in Stage 3). The 3 pipeline stages are deterministic Python scripts. LLM is invoked at exactly 2 specific points — sub-type classification (Stage 1, inline) and AI hook generation (Stage 3, full agent).

The Orchestrator (the agent)

Agent Claude Code Orchestrator

Cron-triggered every Monday 6 AM. Runs the 3 stages in sequence. Handles cross-stage retry/error logic, supervises edge cases (account merges, missing data, API failures).

What "cron" actually means: a scheduled-job trigger. The orchestrator code lives in a Docker container on Cloud Run (or AWS Fargate / Render). Google Cloud Scheduler sends an HTTPS POST to that container every Monday at 6 AM using the cron expression 0 6 * * 1 — minute 0, hour 6, any day-of-month, any month, day-of-week 1 (Monday). The container boots, secrets (SF token, Anthropic key, Amplemarket key, Google service account JSON) are injected via Secret Manager, the orchestrator runs the 3 stages, then the container shuts down. ~30 min total. No always-on infra — pay-per-run, ~$3/month.

Cloud Run · Cloud Scheduler · Secret Manager · Claude Code subagent system invokes Python stage scripts as tools

Input Salesforce query

Pre-pipeline filtering happens natively in SF via territory + account status. Drops customers, active opps, churned <6mo, layoffs, and (via Amplemarket→SF activity sync) already-engaged accounts. Returns ~40k available account IDs. No separate Python "exclusion filter" needed — it's a single SOQL query.

How the orchestrator hits SF: on Monday at 6 AM, Stage 1 authenticates via the JWT bearer flow against a connected app (no user login, runs as a service account), then issues one SOQL query through the REST /query endpoint. Results stream in 2,000-row pages and are loaded straight into Snowflake via the Salesforce Snowflake connector. Pseudocode below.

SELECT Id, Name, Industry, NumberOfEmployees,
       AnnualRevenue, OwnerId, Territory__c,
       Last_Engaged_Amplemarket__c
FROM   Account
WHERE  RecordType.Name        = 'ICP Account'
  AND  NumberOfEmployees      >= 50
  AND  Industry IN ('SaaS','Fintech','B2B Services',...)
  AND  Type                  != 'Customer'
  AND  Active_Opportunity__c  = FALSE
  AND  Churn_Date__c          = NULL
       OR  Churn_Date__c     < LAST_N_MONTHS:6
  AND  Layoff_Flag__c         = FALSE
  AND  (Last_Engaged_Amplemarket__c = NULL
        OR Last_Engaged_Amplemarket__c < LAST_N_DAYS:30)
  AND  OwnerId IN :territory_ids

Per-filter notes: RecordType + Industry + NumberOfEmployees = ICP gate · Type + Active_Opportunity__c + Churn_Date__c = customer/opp state · Layoff_Flag__c = enriched weekly from layoffs.fyi → SF · Last_Engaged_Amplemarket__c = synced nightly from Amplemarket activity webhook → SF custom field · Territory__c/OwnerId = territory split.

The 3 Pipeline Stages

Python Stage 1 — Signal Collector

What: Python ETL. Fans out 10+ API calls in parallel for the ~40k accounts. Signals #1–#10 collected here.

LLM micro-calls (inline): sentiment classifier on signal #7 (pain vs. topical). Role classifier on signal #5 (senior vs. operational hire). Each is a single ~100ms / ~$0.0001 call — not a separate agent.

Clay · RB2B · Clearbit Reveal · 6sense · GA4 · HubSpot/Marketo · Goldcast/Demio · LinkedIn Campaign Manager · Reddit Ads · Common Room · LinkedIn Sales Nav · LinkedIn Jobs · Greenhouse · Lever · Listen Notes · Quartr/AlphaSense · Crunchbase · PitchBook · G2 Buyer Intent · layoffs.fyi · Amplemarket · Salesforce → Snowflake

Python Stage 2 — Scorer

What: Pure deterministic math. No LLM, no agent.

Fit Score (industry × sales motion × growth) + Intent Score (signal weights + multi-signal bonus) → 2×2 matrix → Tier 1/2/3/4 → strongest-signal pick.

reads Snowflake + SF metadata · writes scoring records to SF

Hybrid Stage 3 — Distributor (owner-driven)

Tier 1 (SDR-owned) [LLM Hook Agent]: Generates a 1–2 sentence personalized opener per account from signal evidence (~250 calls/Monday, ~$0.001 each, retry + brand-safety QC). Written to SF custom field ai_hook. When SDR marks Yes, Apps Script creates an Amplemarket draft with the hook pre-filled in step 1 + templated 5-touch structure; SDR composes the email in their voice and sends.

Tier 2 (Auto-owned) [Python only]: Python populates SF custom-field tokens per contact (webinar name, pages visited, competitor name, etc.) and auto-pushes to the matching templated Amplemarket sequence — fires immediately when Stage 3 runs. No SDR action required by default; SDR can override via SF if needed. No LLM.

How the Google Sheet refresh works

Yes — you just open your Google Sheet on Monday morning and it's already updated.

Same Sheet you used last Monday. Same URL, same bookmark, same tabs. The pipeline doesn't create a new file each week — it wipes last week's rows and writes the fresh ones in their place. By the time the SDR opens it at 8 AM, the new Tier 1 list is sitting there waiting.

There's one Sheet per territory (ten total — one per SDR). Each is set up once during Week 2 of rollout: the orchestrator gets edit access, and from then on it can refresh the rows automatically every Monday.

When the SDR flips "Add to sequence" to Yes: the Sheet fires off the cadence in Amplemarket and the row turns to "Sequenced." Tier 2 rows already arrive marked "Sequenced" — the pipeline fired those cadences at 6:30 AM, no SDR action needed.

3Cadence Playbook — Owner-Driven Workflow

Owner determines the workflow, not signal type. Tier 1 (SDR-owned) → AI hook generated per account, SDR composes the email in Amplemarket using hook + signal context. Tier 2 (Auto-owned) → Python pushes contact to one of 10 templated cadences (one per signal) with custom-field tokens populated from signal evidence. Sales leadership owns 100% of templated body copy. AI is bounded to one job: hook generation for Tier 1.

Tier 1 (SDR-owned) — Personalized + AI hook

Cadence column: "Personalized — AI hook ready."

Stage 3 LLM Hook Agent generates a 1–2 sentence opener per Tier 1 account during the Monday batch (~250 calls/Monday). Stored in SF custom field ai_hook. SDR previews in the Sheet → marks Yes → Apps Script creates an Amplemarket draft sequence (hook in step 1 + 5-touch templated structure for steps 2–5, all editable) → SDR opens Amplemarket, composes the email in their voice, sends.

Why no library cadence per signal here: SDRs craft the body. The 10 templated cadences are exclusively for Auto-outreach (below).

4What the SDR Sees — SF Lead View + Google Sheet, One 8-Column Table

Both views are written by the Distribution Layer (Salesforce write-back drives both). Same 8 columns in both. The SF Lead View sits natively in the SDR's daily CRM flow — they triage their Tier 1 list there, click into account records for full context. The Google Sheet is the Monday-morning workspace where the "Add to sequence" column (Yes / No / blank) is editable. Flipping to Yes routes by Owner: SDR (Tier 1) → Amplemarket draft with AI hook pre-filled + SDR composes; Automated (Tier 2) → templated cadence fires automatically.

Concurrent dependency: Cadence Library
The system routes accounts into the cadence library, but the library itself doesn't yet exist at Attention. Building it (~8 templated cadences with body templates, A/B subject variants, deliverability rules) is a parallel workstream owned by sales leadership + growth eng. Worth flagging in the interview as a key v1 dependency.

5SDR Day-in-the-Life

The system is designed around a Monday-morning ritual that makes sequencing decisions almost frictionless.

Monday 6:00 AM

Orchestrator runs the pipeline

Claude Code orchestrator pulls 50k from SF → Python exclusion filter → Stage 1 (Python ETL collects signals + LLM classification) → Stage 2 (Python scorer) → Stage 3 (LLM hook agent for Tier 1 + Python distribution). Total runtime < 30 min.

Monday 6:30 AM

Sheets refreshed + Amplemarket primed

Per-territory sheets refresh with new Tier 1. ~2,000 Tier 2 accounts pushed to Amplemarket programmatic. SF account fields written back.

Monday 8:00 AM

SDR opens cockpit (SF Lead View or Sheet)

Both views show the same 8-column table. SDR triages from the SF Lead View ("47 Tier 1 leads to work today"), then jumps to the Sheet to flip the "Add to sequence" column to Yes / No on each row. ~5 min/account, bulk-action friendly.

Tue – Thu

Work the queue + handle replies

SDR finishes Tier 1 backlog. Replies/bookings flow back via Amplemarket → SF → SDR follow-up.

Continuous (parallel)

Auto-outbound runs unattended

Tier 2 accounts auto-fire when Stage 3 runs Monday morning. No SDR involvement. Replies routed to a shared inbox monitored by the growth team. Booked meetings handed off to AEs.

6Tech Stack Mapping

Every tool in Attention's existing stack maps to a specific role. No new tools required.

ToolRole in this system
SalesforceSource of truth + native per-rep Lead View ("My Tier 1 This Week"). 50k account universe, ICP filter, territory ownership, score/tier/strongest-signal/cadence write-back, opp/customer status, outcome tracking. Drives both the Lead View and the Sheet refresh.
ClayEnrichment + orchestration layer for Stage 1's external feeds (LinkedIn, ATS, Crunchbase, news). Composable workflows the Python ETL calls into.
SnowflakeWarehouse. Append-only signal store + scoring history + Phase-2 ML training data substrate.
AmplemarketOutbound execution. SDR sequences (Tier 1 manual) + programmatic auto-outbound (Tier 2). API-driven push.
Attention(eventually) Conversation intelligence on resulting calls — closes the loop. Outcomes feed Phase-2 model training.
Claude CodeThe orchestrator agent + supervisor. Cron + retry/error handling across the 3 Python pipeline stages. The LLM is invoked at 2 specific points: sub-type classification (Stage 1, inline) and AI hook generation (Stage 3, full agent with retry + brand-safety QC).
Google SheetsEditable workspace over the same 8-column table. Per-territory. Apps Script listens on the editable "Add to sequence" column — when SDR flips a row to Yes, it triggers the Amplemarket API push (using the AI hook already generated by Stage 3). Status syncs back to SF (and therefore to the Lead View).
External feedsG2 / RB2B / 6sense / Clearbit Reveal / Common Room / Listen Notes / Quartr / AlphaSense — called by Stage 1 Python ETL, results landed in Snowflake.
Why this architecture wins: SF as source of truth (analytics don't rot) · Sheets as UI (frictionless, where SDRs already live) · Amplemarket programmatic (scales without people) · 3 Python stages independently testable + cheap to run · Snowflake history (enables Phase-2 ML training data) · LLM bounded to 2 specific tasks (sub-type classification + hook generation; ~$25/week) · No "agent" hype on what's really ETL — defensible to engineering scrutiny.
